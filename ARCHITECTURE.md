# Architecture

## Runtime

Vite builds a static React and TypeScript application. Tailwind utilities and shared CSS variables provide layout and themes. Local JSON tables under `src/data/` feed the `AtlasRepository` interface in `src/repository.ts`. The app checks data integrity before rendering and then builds indexed entity, relationship, source and classification lookups.

`src/focused-network.ts` is the public explorer's immutable presentation layer. It reuses `createIndex`, `loadCapitalResearch`, `indexCapitalPathways` and the verified claim adapter in `src/exploration.ts`. It scores relevant institutions deterministically, keeps individual mechanisms off the default canvas, groups only compatible explicit direct links and never sums financial observations. The 12-candidate cap yields 11 connected initial participants with the current dataset. No path projection creates a bilateral edge.

`FocusedExplorer` owns one network's search, filters, selection, direct/two-hop expansion and temporary mechanism expansion. `FocusedNetworkGraph` renders Cytoscape with deterministic Dagre positions, preserved view contexts and collision-aware insertion of new participants. `CompactPanels` contains brief institution, connection and arrangement summaries. `FullProfiles` is loaded on demand and reuses Sources and PathwayInspector for complete evidence, observations and questions. Three public primary filters use relationship families, explicit geography and researched themes; one advanced section contains consolidated institution types, ownership and documented instruments. The older explorer/control modules remain for their existing consumers and tests but are not mounted in the public App.

`src/entity-taxonomy.ts` retains its consolidated exact-type mapping for the advanced institution filter and existing comparison styling. The focused graph uses neutral institution nodes and distinguishes relationship functions with colours and line patterns. It does not encode institutional role, ownership or financial volume using node colour/size or arbitrary stroke weight.

Public hash routes remain Explore (`#network`), Compare (`#compare`) and About & Methodology (`#about`). Detailed views use `#institution/{encoded original actor ID}`, `#mechanism/{encoded original pathway ID}` and `#relationship/{encoded presentation connection ID}` without adding navigation tabs. Explore stays mounted while profiles are open, retaining filters, selection, expansion, positions and viewport. Browser reload of a detailed institution or mechanism route establishes the relevant Explore context for return. Legacy Research hashes still resolve to `#network` without loading private research data. Static repository subpath assets and legacy URLs are covered by browser tests.

## Data boundaries

Institutions and vehicles share a profile shape and remain separate tables. Relationships join any two atlas entities by stable ID. For a future database, a shared entity ID table can back both subtype tables and support foreign keys for each endpoint. Join tables can hold evidence, aliases, sectors and geographies. Projects and transaction observations are modeled for later use. A transaction can reference one project and a flow shared with other observations. A relationship with a disclosed amount can point to a documented institutional financing event without needing a project entry.

The local repository joins scope assessments and supplemental evidence by stable ID before validation. The full index contains verified entities and verified relationships with both endpoints present. The legacy selectors retain their earlier inclusion rules for compatibility. The public focused selector uses only documented climate-financing relationships and retains matching connection endpoints, pruning isolated nodes when filters are active. Pathway geography is used where recorded; registry-only relationships use explicit shared mandate tags. Search is independent of the initial selection and filter result count. Evidence status validates source use. The comparison tool and profile relationship tabs work across the full verified index.

## Local research flow

The capital pathway research layer is loaded and validated by `loadCapitalResearch(atlas)`. `indexCapitalPathways` associates verified registry edges with pathways by explicit edge reference or by an existing mechanism endpoint. Compact and full profiles resolve original research actors, sources and canonical amounts. Verified research-only connections can appear as explicit institutional links or in an expanded case; non-verified claims remain in full research details with their status. Research-only actors are not promoted into verified registry profiles. Mechanism administration is shown only when the original management/administration link targets that mechanism; downstream administration remains attached to its actual target. See the [capital tracing audit and taxonomy](CAPITAL_TRACING.md).

The international publication reuses three research actor IDs as registry profiles and shares Cuba's existing geography through the registry. Pathway observations support unknown reporting dates with separate access snapshots, alternatives and overlapping financial bases, and institutional or global pool funding scope. The preservation test checks earlier records against the approved publication fingerprints, projecting their original fields after promotion.

The retained research desk component records intake, checks exact normalized names and aliases for duplicates, captures source details and requires a human review decision. Records persist in browser local storage by origin. Seed candidates merge into existing queues by ID and normalized name, with locally saved records taking precedence. Approval marks a candidate as ready for dataset review. Publication is a curated change to the verified JSON tables.

`App.tsx` does not import or mount `Research.tsx` or `research.ts`; there is no public administrative route or client-side toggle. Candidate seed/review tables and browser storage access for those records are excluded from the production bundle. The code remains in the repository for a future separately secured research workspace; a hidden public link would not provide an access boundary. The public app continues loading the capital pathway research layer for read-only inspectors. See the [navigation audit](PUBLIC_NAVIGATION_AUDIT.md) for the full dependency inventory and the private export procedure. The footer links to the repository's correction/missing-mechanism issue template without including browser-local records.

A future research service can submit name or URL inputs, discover sources, extract candidate claims and financial observations, match aliases, propose duplicates, and queue each proposed change with evidence for a reviewer. Use separate candidate and canonical tables plus a review history. A remote repository can replace the local loader while retaining the `AtlasData` contract and verified graph scope.
